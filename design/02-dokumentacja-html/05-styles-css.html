01 Warstwa fundamentu — co robi fundament.css

Warstwa zerowa nad żetonami: wyzerowanie, podłoże dokumentu, typografia bazowa, fokus, zaznaczenie, paski przewijania, drobne wzorce tekstowe. — nagłówek pliku zasoby/css/fundament.css

Fundament nie definiuje ani jednej wartości własnej — każda deklaracja sięga po żeton. Sprawdzone: zero wartości szesnastkowych w całym pliku. Siedem odpowiedzialności, 156 linii.

Przy border-box element zajmuje dokładnie 200 px — wartość zadeklarowana jest wartością zajmowaną. Bez reguły ten sam zapis daje 234 px, czyli wielkość spoza skali 4 px. Cała siatka odstępów przestaje być przewidywalna.

Granica: co należy do fundamentu, a co do komponentu

ŻETONY (zetony.css) ── wartości. Nie zna elementów HTML. │ FUNDAMENT (fundament.css) ── elementy HTML. Nie zna komponentów. │ Jedyna warstwa, której wolno stylować │ goły selektor elementowy. │ KOMPONENTY (komponenty.css)── klasy .dn-*. Nie zna elementów HTML │ inaczej niż przez kotwicę klasową. │ OKNO (arkusz lokalny) ── układ i kompozycja. Nie zmienia wyglądu komponentu, ustawia go w siatce.

Test przynależności reguły do fundamentu — musi spełniać wszystkie trzy warunki: (1) dotyczy elementu obecnego w każdym oknie produktu; (2) jej brak psuje wygląd okna jeszcze przed wstawieniem jakiegokolwiek komponentu; (3) nie da się jej wyrazić żetonem, bo żeton przenosi wartość, a nie zachowanie.

02 Kolejność importu arkuszy

Kolejność jest identyczna w KANON rozdz. 11 i w HANDOFF rozdz. 1 („import po żetonach, przed komponentami”). Nie jest kwestią gustu — każdy krok ma twarde uzasadnienie, a jego złamanie daje widoczny defekt.

Kaskada — kliknij arkusz, żeby zobaczyć skutek jego braku

Komplet arkuszy

Wszystkie pięć warstw obecne w kolejności obowiązującej. Wybierz arkusz powyżej, żeby zobaczyć skutek jego braku.

Miarą jakości podziału jest ostatni wiersz: usunięcie warstwy komponentów pozostawia dokument czytelny. Tak wygląda poprawnie warstwowy system.

Dowód konieczności kolejności 3 → 4

Fundament deklaruje w regule fokusu border-radius: var(--dn-r-xs). Selektor :focus-visible ma wagę (0,1,0) — dokładnie tyle samo, co .dn-btn z promieniem --dn-r-sm. Przy równej wadze rozstrzyga kolejność. Sfokusuj oba przyciski klawiszem Tab albo naciśnij przycisk symulacji.

Promień narożnika przy fokusie klawiaturowym
Kolejność obowiązująca: fundament → komponenty
promień 6 px stały
Kolejność odwrócona: komponenty → fundament
promień skacze 6 → 3 px
Deklaracja promienia w regule fokusu nie jest przypadkiem — obsługuje elementy bez promienia własnego (odnośnik w tekście, <summary>, pozycja spisu treści). Dla nich pierścień byłby ostrym prostokątem, obcym dla systemu o promieniach 3–14 px. Działa jak wartość domyślna, którą komponent nadpisuje samym faktem posiadania własnego promienia — pod warunkiem, że jest importowany później.

Miejsce wspolne.js

Skrypt ładuje się na końcu <body>, nie w <head>. Ustawia data-theme na <html> i obsługuje [data-przelacz-motyw] oraz zapas dla poleceń natywnych commandfor/command. Nie dodaje żadnych stylów — zmienia wyłącznie atrybut, po którym kaskaduje zetony.css. To jedyny dozwolony sposób wpływania JavaScriptu na wygląd w tym systemie.

04 Specyficzność jako kontrakt

Pomiar na pełnym komponenty.css: zero selektorów identyfikatorowych, zero deklaracji !important, sufit specyficzności (0,3,0). To nie jest opis stanu — to kontrakt, którego nie wolno przekroczyć.

Kalkulator wagi selektora

Kolumny wagi: identyfikatory · klasy, atrybuty i pseudoklasy · elementy i pseudoelementy

Przykłady pochodzą wprost z komponenty.css. Wpisz własny selektor, żeby sprawdzić, czy mieści się w kontrakcie.

Drabina specyficzności

(0,1,0) .dn-btn baza komponentu .dn-btn--sygnal wariant ── ta sama waga, wygrywa kolejnością ▼ (0,2,0) .dn-btn:hover stan wskaźnika .dn-btn--atrament:hover stan wariantu ── musi być PO wariancie .dn-btn[aria-pressed='true'] stan trwały .dn-btn.dn-btn--wybrany stan trwały zapisany klasą .dn-krok--poprawny .dn-krok-znak stan rodzica → własne dziecko ▼ (0,2,1) .dn-btn[aria-busy='true']::after stan + pseudoelement ▼ (0,2,2) .dn-tabela tbody tr[aria-selected] struktura natywna tabeli ▼ (0,3,0) .dn-tooltip:hover .dn-tooltip-tresc SUFIT — nie przekraczać

Dlaczego .dn-btn.dn-btn--wybrany ma podwojoną klasę

.dn-btn.dn-btn--wybrany {
  background:   var(--dn-sygnal-tlo);
  border-color: var(--dn-sygnal-obrys);
  color:        var(--dn-sygnal);
}
/* (0,2,0) — przykrywa barwę
   wariantu (0,1,0) niezależnie
   od kolejności w pliku */
aria-pressed = false

Naciśnij przycisk. Wariant sygnałowy (0,1,0) przegrywa ze stanem wybranym (0,2,0) — zawsze, także wtedy, gdy ktoś dopisze nowy wariant na końcu pliku.

Wzorzec do naśladowania przy każdym stanie kolidującym z wariantem: podwój klasę zamiast liczyć na kolejność.

Zakaz zagnieżdżania

Zakazane — zależność od kontekstu

.dn-boczna .dn-btn { border-radius: 0; }
.dn-modal .dn-pole-kontrolka { … }
.dn-karta > div > span { … }
  • przycisk w bocznej nawigacji przestaje wyglądać jak przycisk w modalu — makieta traci wiarygodność,
  • każde zagnieżdżenie wymusza kolejne u tego, kto chce je nadpisać; po trzech iteracjach jedynym wyjściem jest !important,
  • reguła nie ma domu przy podziale na pliki — nie należy ani do boczna.css, ani do przycisk.css.

Dozwolone — mechanika wewnątrz komponentu

.dn-wpis--czlowiek .dn-wpis-medalion { … }
.dn-krok--poprawny .dn-krok-znak { … }
.dn-tooltip:hover .dn-tooltip-tresc { … }

Kryterium: oba człony selektora należą do tego samego komponentu i trafią do tego samego pliku. Jeżeli tak — zagnieżdżenie jest opisem wewnętrznej mechaniki, a nie zależnością od kontekstu.

  .dn-pole-kontrolka:focus,
  .dn-pasek-szukaj:focus,
  .dn-prompt:focus-within { outline: var(--dn-wym-fokus) solid Highlight; outline-offset: 0; }
  /* stan wybrany: kolor tła znika — wskazanie przejmuje obrys */
  .dn-tabela tbody tr[aria-selected='true'],
  .dn-boczna-pozycja[aria-current='page'] { outline: 1px solid Highlight; }
  /* kropka sygnału: pierścień tętna znika — kropka dostaje obrys systemowy */
  .dn-kropka { outline: 1px solid CanvasText; }
}

          

          

            Zapis używa słów kluczowych systemowych (Highlight,
            CanvasText) — jedynych wartości sensownych w tym trybie, bo żetony i tak są
            nadpisywane przez system. To jedyne miejsce w pakiecie, gdzie wolno napisać barwę spoza
            var(--dn-*), i wyłącznie jako słowo kluczowe, nigdy wartość szesnastkową.
            Zakres: niecałe 15 linii w fundamencie, zero zmian w komponentach.

Pułapka: żetony punktów łamania nie działają w @media

            
Własności niestandardowe nie są dozwolone w warunku zapytania medialnego.
