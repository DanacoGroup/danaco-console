01 Odbiorca, zakres, regulamin budowy

Pakiet wizualny przechodzi z katalogu projektowego do budowa/client/src. Odbiorcą jest deweloper wdrażający; rozliczeniem — działająca aplikacja w obu motywach, bez #000000, bez disabled, z pomiarem kontrastu zamiast deklaracji.

1.2. Cztery reguły nienaruszalne

Jedna odpowiedzialność = jeden plik

Żeton barwy nie mieszka w pliku komponentu. Komponent nie definiuje żetonu.

Arkusz ≤ 300 linii

komponenty.css (1207 linii) → 14 plików. zetony.css (448 linii) → 12 plików.

Wyłącznie żetony semantyczne

.dn-btn używa --dn-atrament, nigdy --dn-szary-900.

Wartości przenosi się dosłownie

Podział pliku to operacja mechaniczna. Zero „przy okazji poprawiłem odcień”.

Pięć zmian, których nie da się wykonać samą podmianą arkuszy.

Pięć zmian kontraktowych
1

Wykaz nazw zaktualizowany do manifest.json — 82 pozycje, nazewnictwo polskie opisowe. Literówka ma dalej zatrzymywać kompilację: wykaz jest typem, nie łańcuchem znaków. Barwa currentColor, renderowanie 14/16/20/24 px.

Usunąć lokalne zmienne --dc-*; przepiąć wpisy na .dn-wpis, pole na .dn-prompt, wskaźnik na .dn-postep, zastosować mapowanie ról z rozdz. 04.

3

Motyw

Mechanizm bez zmian: data-theme + zapas prefers-color-scheme. Wartości nowe. color-scheme ustawiane per motyw. Pasek górny zawsze atramentowy. Oba motywy definiowane osobno, nie wywodzone.

4

Gęstość

Domyślnie zwarta. Przełącznik przyszłościowo przez data-gestosc="przestronna" na <html> — żetony gotowe (sekcja 13). Dotyk podnosi wymiary sam przez pointer: coarse. Przełącznik gęstości działa na pasku górnym tego opracowania.

5

Zero blokad

Przy wdrażaniu komponentów nie dodawać disabled. Zamiast blokady — komunikat po naciśnięciu albo opis obok.

05 Cztery fale wdrożenia i brama weryfikacyjna

Kliknij falę na osi, żeby zobaczyć jej zakres, warunek wejścia i pełną bramę weryfikacyjną.

──────► ──────► ──────► ──────►
Brama weryfikacyjna każdej fali: porównanie z makietami w obu motywach oraz przebieg kontrasty.json — pomiar, nie deklaracja.

5.1. Trzy konsekwencje operacyjne reguły bramy

  1. Oba motywy zawsze. Zaliczenie w jednym motywie nie jest zaliczeniem — motywy są równoprawne, więc bramę przechodzi się dwukrotnie.
  2. Pomiar, nie deklaracja. „Kontrast wygląda dobrze” nie jest wynikiem. Wynikiem jest liczba z algorytmu WCAG i werdykt wobec progu.
  3. Fala nie zamyka się częściowo. Fala 2 nie startuje przed zamknięciem fali 1 — komponenty odczytują żetony, których jeszcze nie ma.

12 Wzorce implementacyjne

Kod poniżej jest cytatem z biblioteki — nie propozycją. Przycisk kopiowania obok każdego bloku.

13 prefers-reduced-motion — co dokładnie się dzieje

Obsługa jest globalna, w żetonach — nie per komponent. Działają dwa mechanizmy naraz: podmiana żetonów czasu (źródło prawdy) i reguła * z !important (siatka bezpieczeństwa dla czasów spoza skali, np. 0,8 s spinnera).

@media (prefers-reduced-motion: reduce) { :root { --dn-czas-1: 0.01ms; --dn-czas-2: 0.01ms; --dn-czas-3: 0.01ms; --dn-czas-tetno: 0.01ms; } *, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; } }

13.1. Tętno → pierścień statyczny

Skrócenie czasu wygasza ruch, ale usunęłoby też informację: kropka pracująca stałaby się nieodróżnialna od zwykłej. Dlatego biblioteka podstawia zamiennik statyczny.

Ten sam stan, dwa nośniki — porównanie obok siebie
RUCH DOZWOLONY
Kolejka pracuje — 12 z 34 zadań

Nośnik informacji: ruch (pierścień rozchodzi się co 2,4 s).

RUCH OGRANICZONY
Kolejka pracuje — 12 z 34 zadań

Nośnik informacji: kształt (pierścień statyczny 2 px). Informacja zachowana.

Zasada ogólna: ograniczenie ruchu nie może usuwać informacji. Jeżeli ruch był jej jedynym nośnikiem, przejmuje ją kształt, obrys albo etykieta.

13.3. Czego NIE robić

  • Nie dublować zapytania prefers-reduced-motion w każdym komponencie — obsługa jest globalna, duplikat rozjedzie się przy pierwszej zmianie.
  • Nie wykrywać preferencji w JavaScript i nie zdejmować klas — preferencja może zmienić się w trakcie sesji, CSS reaguje sam.
  • Nie usuwać zamiennika przy reduce — to usuwa informację o stanie systemu.

Wybór własności CSS to wybór etapu potoku renderowania. Trzy poziomy kosztu, dwie własności bezpieczne.

14.1. Dlaczego pasek postępu może animować width

Element leży wewnątrz toru z overflow: hidden i stałą wysokością 4 px. Przeliczenie układu ogranicza się do jednego elementu i nie propaguje na rodzeństwo. Zamiana na transform: scaleX() rozciągałaby zaokrąglenia narożników — pogorszenie wizualne bez zysku pomiarowego przy jednym pasku na widok.

14.2. will-change — zasada trzech warunków

1Animacja długa lub cykliczna

tętno, spinner — nie jednorazowe przejście

2Znany, ograniczony rozmiar

warstwa kompozycji kosztuje pamięć proporcjonalnie do powierzchni

3Deklaracja zdejmowana

po zakończeniu animacji; na stałe w arkuszu = przeciwieństwo optymalizacji

Stan biblioteki: komponenty.css nie deklaruje will-change nigdzie. Animowane elementy są małe (kropka 6 px, spinner 14 px, pierścień AOD 36 px) i przeglądarka promuje je sama. Wprowadzenie wymaga pomiaru pokazującego zysk.

16 Kontrast: metoda, komplet 33 pomiarów, zasada tekst-3

16.1. Metoda pomiaru

   1. Kanał znormalizowany:      c = C / 255                    (C ∈ ⟨0,255⟩)

   2. Linearyzacja kanału:       c ≤ 0,03928  →  c / 12,92
                                 c >  0,03928  →  ((c + 0,055) / 1,055) ^ 2,4

   3. Luminancja względna:       L = 0,2126·R + 0,7152·G + 0,0722·B

   4. Kontrast pary:             K = (L_jaśniejsza + 0,05) / (L_ciemniejsza + 0,05)

   5. Barwa z kanałem alfa:      przed pomiarem złożyć z tłem
                                 wynik = barwa·α + tło·(1 − α)
